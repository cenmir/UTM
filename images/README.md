# images/

Figures used by the slide decks and the analysis scripts. These were loose in the repository root
until 2026-08-25; the names always said which test series they belonged to, so the folders just
make that visible.

| folder | what is in it |
|---|---|
| `V4/` | 8.6.19 / 8.6.3 staircase and linearity series |
| `V5/` | 8.6.20 V5 tensile-to-failure, and the V5a/b/c comparison set |
| `V6/` | V6 quintet — ductility, fracture patterns, offset factor, repeatability |
| `V6a/` | V6a 100 % infill series, including the V6a-vs-V5 overlays |
| `features/` | `feat_*` — proof figures for app features (auto-stop, strain rate, DIC halt …) |
| `rig/` | hardware and UI: enclosure CAD, DIC HUD and Settings screenshots, preload schedule |

Not to be confused with:

- **`graphics/`** — rig documentation referenced from `README.md` and `PROJECT_REQUIREMENTS.md`
  (GUI, schematic, dimensions). Different audience, so it stays where the docs point at it.
- **`documentation/*.png`** — figures generated by the deck builders that live beside them, and
  are rewritten on every build.

## If you move one of these

The scripts `chdir` to the repository root, so every reference is a path from the root such as
`"images/V6a/V6a_stress_strain.png"`. Grep for the filename before moving it — and note that
`pic_or_ph()` in the deck builders substitutes a PLACEHOLDER BOX for a missing image rather than
failing, so a broken path produces a deck that builds cleanly and is quietly wrong. After any
move, rebuild and check the picture count is unchanged:

```
python documentation/generate_v6a_slides.py
python -c "from pptx import Presentation; p=Presentation('documentation/V6a_8_6_20_slides.pptx'); \
print(sum(1 for s in p.slides for sh in s.shapes if sh.shape_type==13), 'pictures')"
```

At the time of the move that was **90 pictures across 125 slides**.
